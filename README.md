# Ventana

> AI 虚拟角色聊天 App —— 住在这台手机里的一个小房间。
>
> 纯原生 HTML + CSS + JavaScript，**零依赖、无构建步骤**，以 PWA 形式安装到手机主屏。

## 现在做到哪了

**一句话**：骨架在跑，视觉还是黑白试验版。

| 已经有了 | 还没有 |

| OpenAI 兼容接口的真实 API 接入（含「试一试」连通性自检） | 多设备同步（一切都在本机 localStorage） |

| **每条气泡下的菜单：复制 / 重新生成 / 删除** | 消息编辑、引用回复 |
| **会话归档**：归档 + 开新会话；已归档的在记忆馆顶栏箱子抽屉里导出 txt / 删除 / 改名 | 归档的批量导出 / 导入 |

| **记忆馆**：AI 自己读写摘要，带时间戳，按需取正文 | 记忆的手工编辑（目前只能看和删） |
| 移动端优先布局（safe-area、键盘避让、触摸目标 ≥38px） | 桌面端形态 |
| 对话 / 人格 / 文档 / 记忆全部持久化到 localStorage | 导出 / 备份（整包） |
| 深浅两套主题跟随系统 | 主题手动切换、配色体系 |
| 可安装 PWA（manifest + service worker 离线可用） | 图标与启动画面精修 |
| 像素级自动化测试（273 项，见下文） | —— |

**方向已经调整**：原计划的"多角色 + 角色卡"**不做了**。
现在只有一个对话对象，它的性格由「连接设置 → 系统提示词」决定。
人格是**一整段纯文本**，整段替换而不是多份拼装 —— 界面上那段就是最终送给模型的那段。

界面配色目前刻意只用黑与白（`tests/mobile.mjs` 里有一条断言在守着：
聊天界面任何元素都必须 R=G=B）。**加颜色的时候记得同时改那条断言。**

## 跑起来

```bash
python3 ventana/serve.py          # 端口 5210，不缓存，并把手机可访问的地址打印出来
# 浏览器打开 http://127.0.0.1:5210
```

`serve.py` 有两个作用：**发 `no-store` 头**（否则浏览器缓存 + Service Worker 会让你
"改了代码看不到"），以及**打印局域网地址**，方便手机直接打开：
终端会输出类似 `手机（同一个 Wi-Fi）：http://192.168.x.x:5210/` 的一行，用手机输进去即可。

或者在工程根目录双击 **`Ventana启动.command`**：它会先真发一次 HTTP 请求判断服务是否健康
（只检查端口是否被占用是不够的——`http.server` 卡死时端口仍在 LISTEN，浏览器看到的是
`ERR_EMPTY_RESPONSE`），识别到「占用但无响应」会清掉卡死进程再重启。

注意 **`file://` 直接打开也能跑，但 PWA 安装和 service worker 只会在 http(s) 下生效**
（`index.html` 里已经做了协议判断，`file://` 下会自动跳过注册）。

## 目录结构

```
ventana/
├─ index.html              结构（约 240 行）
├─ styles.css              样式（约 480 行）
├─ app.js                  逻辑（数据层 / 流式 / 工具调用 / 三个视图渲染）
├─ manifest.webmanifest    PWA 清单
├─ sw.js                   Service Worker（导航请求网络优先，其它缓存优先）
├─ serve.py                开发用静态服务（不缓存 + 打印手机访问地址）
├─ README.md / HANDOFF.md  说明与交接文档
├─ doc-bigram-snippet.md   大文档按需截取的 bigram 打分逻辑说明
├─ icons/                  192 / 512 图标
└─ tests/
   ├─ cdp.mjs              零依赖 Chrome DevTools Protocol 客户端
   ├─ png.mjs              够用的小 PNG 解码器（读像素用，见下文）
   ├─ mobile.mjs           移动端验收测试 273 项（像素 + 计算样式 + 交互 + 人格 + 资料库 + 记忆馆 + 归档 + 顶栏导出 + 内置浏览器导出面板 + 软键盘可见性 + 图标布局 + 缓存自愈 + 记忆馆感叹号 + 更新后全量下发 + 大文档按需截取）
   └─ shots.mjs            逐状态截图（日间/夜间各 7 个状态 + 桌面参考）
```

**为什么拆成三个文件**：一开始确实是单文件。加到四个大功能（资料库、气泡菜单、
会话归档、记忆馆）之后，单文件逼近 2000 行 —— 改一行要在两千行里找上下文。
所以在加功能之前先拆成了「结构 / 样式 / 逻辑」三层。

**没有引入任何构建步骤、依赖或模块系统**：仍然是 `python3 serve.py` 就能跑的静态站点，
"拷一个目录就能用"这个性质没变（这条是给"以后并进别的项目"留的余地）。
再往下拆（比如按视图拆 `views/`）的时机，是这三个文件里任何一个超过 1500 行的时候。

## 测试

测试是**浏览器里真跑**的，不是读源码。前置两步：

```bash
# 1) 起静态服务（不缓存，改完刷新就能看到）
python3 ventana/serve.py

# 2) 起一个带调试端口的无头 Chrome
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless=new --remote-debugging-port=9222 \
  --user-data-dir=/tmp/ventana-cdp --no-sandbox --disable-gpu \
  --disable-backgrounding-occluded-windows --disable-renderer-backgrounding \
  --disable-background-timer-throttling --window-size=390,844 about:blank &

# 3) 跑验收（273 项，约 46 秒）
node ventana/tests/mobile.mjs /tmp/ventana-shots

# 4) 想肉眼核对画面，再跑一遍截图（日间/夜间各 7 个状态 + 一张桌面参考）
node ventana/tests/shots.mjs /tmp/ventana-shots
```

> **macOS 上必须加 `--no-sandbox`**。不加会以 `Failed to initialize sandbox` 直接崩，
> 连调试端口都起不来（本机 DSH 沙箱限制了 Chrome 自己的沙箱初始化）。
>
> 后面三个 `--disable-*-background*` 是**必需**的：无头 Chrome 会把页面判成不可见
> （`document.hidden === true`），于是**渲染帧不产生、定时器被节流**，
> 流式打字会变成"字都到了但屏幕上一个字不出"。加上它们页面才会被当作可见。

### 这份测试怎么想问题的

`tests/` 里的断言分三层，**越往下越接近真相**：

| 层 | 例子 | 能发现什么 |
|---|---|---|
| 计算样式 | `getComputedStyle(bubble).borderRadius === '18px'` | 声明有没有生效 |
| 像素采样 | 截图 → 自己解码 PNG → 采样气泡左上角 | **画出来到底长什么样** |
| 交互时序 | 发送 → 三点 → 光标 → 多条 → 停止 | 状态机有没有漏 |

之所以要自己写 PNG 解码器（`png.mjs`）：`Page.captureScreenshot` 只给 base64，
而「气泡到底是不是方块」这种问题读 CSS 声明是读不出来的——声明里明明写着
`border-radius: 18px`，画出来仍可能是通栏方板。**上一轮被报告的夜间模式 bug
就是这样漏过去的。** 判据见 `mobile.mjs` 里的注释。

### 写这类测试踩过的坑（不要再踩）

1. **旧 Service Worker 会骗你 —— 已经被坑过两次。**
   第一次：`sw.js` 对 index.html 用缓存优先，改了代码刷新三次还是旧页面（现在导航请求是网络优先）。
   第二次（改名后）：`127.0.0.1` 打开是旧版、局域网 IP 打开是新版 —— 每个 origin 各有一份缓存，
   而且 **`sw.js` 自己也会被浏览器缓存**（最长 24h，`no-store` 对 SW 脚本无效）。
   对策：注册 URL 带版本号 + 缓存命中时 SW 通知页面自动刷一次。
   **硬规矩：每次改 `sw.js` 都要同时升 `index.html` 和 `sw.js` 里的 `VERSION`。**
   详见 `HANDOFF.md` 第 7.5 节。
2. **`Page.addScriptToEvaluateOnNewDocument` 每次新文档都会执行。**
   用它清 localStorage 时必须在首次加载后移除，否则后面每一次刷新都会把数据洗掉，
   测出来像"持久化失效"。
3. **别去轮询只存在几十毫秒的瞬时 DOM 状态**（比如"气泡间停顿 + 只有三点"）——
   窗口比轮询间隔还短，永远对不上。改成验证确定性的不变量（比如"停止后整屏没有
   光标/三点/空气泡"）。
4. **静态服务必须起在 `人机恋/ventana/`**。本机另一个工程里也有同名目录，
   起错目录会看到完全另一个 App，而且现象是"我的改动毫无效果"。

## 界面约定（改之前先看这里）

结构对齐参考实现 [dwell-on-something](https://github.com/xinwithyu/dwell-on-something)：

```html
<div id="log">                         <!-- 消息流，flex column，gap 18px -->
  <div class="tstamp">14:20</div>      <!-- 隔 5 分钟以上才插一条 -->
  <div class="row">      <div class="body reply">…</div></div>   <!-- 对方：纯文字 -->
  <div class="row me">   <div class="body bubble">…</div></div>  <!-- 我方：气泡 -->
  <div class="row sys">  <div class="sysline">…</div></div>      <!-- 系统事件 -->
</div>
```

几条硬规矩：

1. **对方的回复不是盒子。** 只给排版（字距、行高），不给背景、边框、圆角。
   上一版给对方的回复套了通栏灰底方块，夜间模式下整屏都是方板——这是被报告的 bug。
2. **行与行之间的留白归 `.row`，气泡自己的 padding 归 `.bubble`。** 以后加头像时
   只用动 `.row`，不用碰气泡。
3. **输入卡是 `position: fixed` 的**，消息区用 `--composer-h`（JS 实测后写进 CSS 变量）
   在底部留出避让空间。改输入卡高度不用改消息区的 padding，ResizeObserver 会跟。
4. **界面里不出现 emoji。** 部分安卓会把 emoji 渲染成彩色方块，直接破坏黑白约定；
   所以齿轮之类的装饰都用内联 SVG，实在要用文字代替的就用「」里的中文字。
5. **触摸目标不小于 38px**，手机上手指比鼠标粗得多。

6. **行结构是 `.row > .col > (.body + .acts)`**：`.row` 只管靠哪边，`.col` 竖排。
   图标排必须是 `.col` 的子元素，不能直接挂在 `.row`（那是横排 flex，会把它挤成一列）。
7. **每条消息的图标由 `attachActions()` 统一挂**，而且必须是幂等的
   （同一个节点重复挂会出现两层图标，看起来像"删一次少两条"）。
   **一轮回答挂在哪**由 `attachActionsToReply()` 决定：挂**最后一个有内容的气泡** ——
   挂在第一条下面的话，图标会夹在两段话中间（作者报过这个 bug）。
8. **AI 的回复可能被拆成多条气泡**（工具调用会打断它）。所以"一轮回答"对应的是
   一个数组 `replyEls`，不是单个节点 —— 处理停止/重新生成时别只盯最后一个。
9. **标记行不进气泡**：`[[读:…]]` / `[[记:…]]` / `[[忆:…]]` 这类协议行会被执行成
   居中系统事件，正文才画成气泡。流式时只要发现 `[[` 就先不画，避免半截标记闪一下。

## 接真实模型

顶栏那个胶囊（或右边齿轮）→「连接设置 → API 连接」：

1. 填 **Base URL**（如 `https://api.deepseek.com/v1`）、**API Key**、**模型名**
2. 点「试一试」发一次 `max_tokens: 1` 的最小请求确认能通
3. 点「保存」—— 三项齐了**自动**切到真实 API

**没有"模式开关"，演示模式也不需要手动开启**：三项没填完就是演示模式，
填完就是真实 API。这是算出来的状态，不是存下来的设置 ——
所以不会出现"滑块停在演示模式但其实已经配好了"这种自相矛盾。
想回到演示模式，点「清除连接」（人格不会被一起清掉）。

支持任何 OpenAI 兼容端点（DeepSeek / OpenAI / Kimi / GLM / 自建）。
**API Key 只存在本机 localStorage，由浏览器直连你填的接口，不经过任何服务器。**
（localStorage 不加密，共用设备时注意。）

参数建议：

| 参数 | 建议 | 理由 |
|---|---|---|
| temperature | 0.85–1.0 | 太低会变客服腔 |
| max_tokens | 150–300 | 控制长度的最强杠杆 |
| presence_penalty | 0.3–0.6 | 抑制重复句式 |

## 怎么设置它的人格

「连接设置」往下滚 → **系统提示词 · 决定它是谁**。

- **直接打字**：写给模型看的第一段话。写完点「保存人格」，或按 `Ctrl/⌘ + S`。
  返回对话时如果没保存，也会静默存下来（不吞你的字）。
  手机上点进去弹软键盘时，输入框会自动滚到键盘上方，不会被键盘压住（v0.12 修）。
- **上传文件**：「选择文件」，支持 `.md` / `.markdown` / `.txt` / `.json` / `.yaml`，
  包括 skill.md 这类人物设定文档。**上传是整段替换**输入框里的内容。
- **清空**：`清空` 按钮把人格清掉，回到"通用助手，没有性格"。

几条设计上的取舍（改之前先想清楚）：

| 决定 | 为什么 |
|---|---|
| 只有**一份**人格，整段替换 | 多份怎么拼是产品决策，拼错了比不拼更糟。要有第二个人格，就换文件 |
| 格式不做解析 | 模型看到的是纯文本。skill.md 是"内容长什么样"的约定，不是格式规范 |
| 空着就不发 system 消息 | 不塞默认人格。空人格 = 通用助手，这是可预期的默认 |
| 400KB 硬上限 + 8000 字软提示 | 提示词每一轮都会整段发出去，越长每轮越贵。软提示不拦人，只提醒 |
| 人格只存 localStorage，不上传 | 和 API Key 一个策略：不经过任何服务器 |

**改人格不用重开对话**：下一轮就会带上新的系统提示词（它不写进历史记录里）。
反过来说，**历史里不会留下"当时用的是哪版人格"** —— 以后要做"考古"需要另外记录。

## 开场白

进门那段「你好，我是 Ventana……」**接上 API 之后也一直留着** —— 它的排版（衬线大标题 +
分段引导）是这个界面气质的一部分，去掉就掉档次。

它的文本按连接状态自动换：

| 状态 | 内容 |
|---|---|
| 演示模式 | 说明现在是内置回复，并给出接入的三步 |
| 已接上模型 | 换成"已经接上模型了"，并提示人格与资料库在哪 |

保存或清除连接后**不刷新页面**就会换过来。

两个刻意的设计：

- **它不挂操作图标**（复制/删除/重新生成）—— 它是引导文案，不是对话
- **它不进发给模型的历史** —— 它不是角色说的话。进历史既白占 token，
  又会让模型以为"自己刚说过一句自我介绍"

> 实现上它是 `greet: true` 的一条**真实消息**（所以有索引、能持久化、
> 渲染时带那个「Ventana」大标题）。连接状态一变，`refreshGreeting()`
> 会把已存的那条重写一遍 —— 不重写的话，接上模型后屏幕上还挂着
> "现在还是演示模式"，看起来像没生效。

## 资料库：让 AI 按需读长文档

「连接设置 → 资料库」上传 `.md` / `.txt` / `.json` / `.yaml`（可以一次传多份）。

**它和系统提示词是两回事，不会互相覆盖：**

| | 系统提示词 | 资料库 |
|---|---|---|
| 放什么 | 它一贯的样子（性格、说话方式、底线） | 设定集、日记、世界观、参考笔记 |
| 每轮都发吗 | **是**，每一轮都带上 | **不是**，只发一份**索引**（标题 + 开头 60 字） |
| 长度 | 建议 8000 字以内 | 可以很长（单份上限 2MB） |
| AI 怎么拿到 | 直接就在上下文里 | 需要时**主动索取**：调 `read_doc` 工具，或输出 `[[读:文档名]]` |

索取的时候聊天里会多出一行居中的系统事件（`读了《世界观.md》（3200 字）`），
你能看见它读了什么 —— 不是偷偷读的。

**为什么这么做**：文档每一轮都塞进提示词的话，你得为它每一轮付钱，
而且大多数轮次根本用不到。索引 + 按需读取，长文档的固定开销只有几行。

**超过 6000 字的大文档自动按需截取（v0.14 起，v0.15 补齐）**：索取时不再整篇给，
只给与**当前话题最相关**的部分（最多 6000 字，向命中段落两侧扩展保持连贯）。
**文本协议（`[[读:文档名]]`）和原生工具调用（`read_doc`）两条路都截取**——两万字、
四万字的文档也最多烧 6000 字 token。截取后聊天里的系统事件会如实写
「读了《文档名》· 给了多少/总字数（按需截取）」，不会再把整篇总字数当"读了全文"展示；
模型侧 `read_doc` 的工具描述也明确写着"长文档按需截取、最多 6000 字、不会整篇输出"，
从根源上消除"索取 = 拿全文"的误解。实现细节见 **`doc-bigram-snippet.md`**。

拿不准相关段落时会如实告诉模型「没找到与当前话题直接相关的部分，先给开头部分」。
唯一整篇下发的时机是资料库刚更新后的那一次（见下一条），属于有意的设计。

**更新后下一轮全量下发一次（v0.14）**：只要你在设置页**改过系统提示词，或增删过资料库文档**，
下一轮对话会把「系统提示词全文 / 资料库全部文档全文」整段随消息发给 AI 一次
（前面带「【系统提示词刚刚更新】/【资料库刚刚更新】」声明），让模型立刻知道内容变了；
只发这一轮，下一轮恢复默认读取方式（人格全文依旧带，文档只给索引按需取）。

## 记忆馆：让 AI 自己记住

顶栏的「记忆馆」。**里面的内容全部由 AI 自己写**，没有手工新建表单 ——
所以它不会退化成一个需要你维护的待办列表。

三种触发方式（你只需要正常说话）：

| 你说 | 它做什么 |
|---|---|
| 「记住这件事：…」 | 写一条摘要 + 时间戳进记忆馆 |
| 「上下文太长了，压缩一下」 | 把前面几轮压成一条摘要写进去 |
| 「记住刚才这 N 轮」 | 按你点的范围写一条，更早的写成概括 |

它写的时候聊天里会出现一行「记下了 · <标题>」。
顶栏的「记忆馆」**不直接显示条数**（v0.14 起不再显示数字），只做两件事：

- **没有新内容**：安静的「记忆馆」三个字
- **有新内容**（AI 刚写入过、你还没看）：旁边亮一个**感叹号**；点进记忆馆看过一次后回到对话，感叹号就消失了

**总条数在记忆馆里面显示**（"共 N 条记忆"），不进馆看不到。
**平时它只看得到标题索引**，需要正文时自己取（`[[忆:标题]]` / `read_memory` 工具）。

右上角那个箱子图标 → 从右侧滑出**已归档会话抽屉**：导出 txt、删除、改名。归档会话按创建时间排列；它只在抽屉里，不占记忆馆主体的空间。

## 会话：归档与导出

「连接设置 → 会话 → 归档当前会话并开新的」，已归档的在**记忆馆顶栏箱子弹出的抽屉**里管理。

**顶栏的下载图标**（对话右上角）＝一键导出**当前正在聊的会话**为 txt，不需要先归档；点击直接把整个会话（标题 + 起止时间 + 每句消息的时间和说话人）下载成 `会话标题.txt`。

> **内置浏览器（微信/企微/钉钉等）里下载不了文件**：`a[download]` 在这些 WebView 里不可靠，点击会把 blob 链接当导航打开、跳转后必白屏（v0.13 前手机端导出的实际表现）。v0.13 起下载按环境分叉——系统浏览器照旧直接下载，内置 WebView 改成在页面内弹出**导出面板**：全文摊在只读文本框里，可一键「复制全文」或长按全选后粘贴到备忘录保存，不再跳浏览器。

- 归档**不会删除任何东西**：它只是打个标记，数据一直保留在本地（抽屉里只能导出 / 删除 / 改名，想继续聊得开新会话）
- 归档后自动开一个新会话（不会留下"当前会话是已归档的"这种怪状态）
- 导出是纯文本 txt：带标题、开始/结束时间、每条消息的时间与说话人
- 删除有二次确认（没有导出过的话，删了就真没了）

## 每条消息下面的小图标

每条气泡/文字下面有一排小图标：**复制 / 重新生成 / 删除**（我方消息没有「重新生成」）。

位置是刻意的（**作者明确要求过，别再挪**）：

| 谁的消息 | 图标贴哪 | 为什么 |
|---|---|---|
| **我发的** | 气泡的**右下角** | 气泡本身靠右，图标跟着靠右才是一个整体 |
| **AI 回的** | **整段消息**的左下角 | 一段回复可能是多条气泡（连发/工具调用），图标挂**整段**的末尾，不是中间那条 |
| 开场白（Ventana 那段） | **没有**图标 | 它是引导文案，不是对话 |
| 全部 | **永远横向一排**（`nowrap`） | 短消息也不会折成竖排 |

其它两条：

- 图标本体 16px、点击区 36×30 —— 图标要小、手指要够得着，只能靠内边距调和
- 生成过程中不挂图标（挂了也能点，但点了会出错）

**这些图标不只是改界面，它们直接改存储** —— 删掉就是真删掉，刷新后不会回来。
「重新生成」= 从这条回答开始往后全部丢掉、重新问一次，所以天然支持"从断掉的接着来"。

> 布局上有个坑记在这：`.acts` 必须挂在 `.row > .col` 里，**不能**做 `.row` 的直接子元素 ——
> `.row` 是横排 flex，图标排会被当成"再开一列"，在窄屏上被挤成几十像素宽。
> 另外 `.row.me .col` 不能设 `align-items: flex-end`，否则图标排的负外边距会被对齐计算吃掉，
> 图标会偏出气泡左缘 10px。两件事都有断言守着（`mobile.mjs` 的「气泡菜单」与「横向溢出」两组）。
